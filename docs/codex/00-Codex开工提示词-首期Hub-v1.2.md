# COMAC 青年 AI Agent 创新实践月｜Codex 开工提示词（阶段一：高质量网页 Hub｜开工包版）v1.2

> 本文件由仓库根目录 `AGENTS.md` 调度；也可单独整体交给 Codex。当前阶段只交付高质量、真实可运行、可继续扩展的网页 Hub；不要提前铺开完整 AI Coach、评委工作台、组织者中枢或后端系统。

你现在是本项目的**首席产品工程师、交互设计师和前端架构师**。请直接进入开发，不要停留在概念说明、线框图或静态截图阶段。

要构建的产品是：

**COMAC 青年 AI Agent 创新实践月网页 Hub（阶段一）**

它面向第一次打开网页的青年员工，必须在很短时间内回答四个问题：

1. 这是什么活动？
2. 为什么值得参加？
3. 我会经历什么？
4. 我现在应该做什么？

当前阶段的目标不是做“大而全的平台”，而是先做出一个：

- 能打开；
- 能讲清楚；
- 能产生兴趣；
- 能让不同角色找到下一步；
- 有真实交互与动效；
- 可作为后续完整网页中枢的可靠前端底座。

先审计仓库，然后立即实现。

1. 读取现有仓库结构、依赖、路由、样式、组件、测试和未提交工作；

7. 最终必须交付真实可运行代码，不能用设计图、伪代码或静态截图冒充实现。

## 3. 产品宪法

所有设计与代码必须遵守：

1. **强编排，弱干预。** 系统控制信息出现顺序，不替用户得出结论。
2. **一问一幕，一幕一决策。** 任一时刻只出现一个主问题和一个主要动作。
3. **当前场景优先。** 不用长聊天流、复杂侧栏和表单墙抢夺焦点。
4. **业务故事优先。** 先讲真实问题与价值，再讲 Agent、Workflow、RAG 等技术。
5. **AI Coach 不迎合用户。** 它严格但建设性，像评委和创新教练，而不是夸奖型聊天机器人。
6. **平台不承担 Coding。** 平台帮助思考、沉淀、交接和接回证据，实际构建在外部工具中完成。
7. **证据优先于完成率。** 后续完整产品采用“主张—证据—缺口”，不是 KPI 分数。
8. **AI 没有人的裁决权。** 参赛者、评委和组织者保留最终判断。
9. **安静的认知画布。** 不是企业驾驶舱、监控大屏、赛博朋克控制台或通用 SaaS 模板。
10. **动态必须帮助理解。** 动效只用于“端上来、收拢、吸附、长出来、取到眼前、退到背景、凝结”。

## 5. 页面信息架构

当前阶段优先做一个连续、沉浸、滚动节奏明确的主页 `/`，并用少量轻量路由承接角色下一步。

建议路由：

```text
/                     公共 Landing / Hub
/start                AI Coach 轻量预览，可由主页 CTA 打开
/guide                活动说明与参与路径
/role/participant     参赛者下一步说明
/role/reviewer        评委下一步说明
/role/organizer       组织者下一步说明
/dev/scenarios        组件、状态与动效验收页
```

不要为了“看起来像平台”再创建十几个空路由。

### 主页模块顺序

#### A. 顶部导航

- 品牌文字；
- `活动介绍`；
- `实践路径`；
- `不同角色`；
- `常见问题`；
- 主 CTA：`开始探索`。

若仓库提供官方 Logo，使用官方资产；若没有，只使用克制的文字标识和中性几何标记，不自行伪造官方 Logo。

#### B. Hero

- 左侧或中央：主标题、副标题、双入口；
- 右侧或中央：抽象 Coach 光核；
- 初次加载分三拍出现：品牌与标题 → Coach 光核 → 两个入口；
- 首屏尽量在 1440×900 内完整呈现，不被后续内容挤压。

#### C. “这不是一次普通比赛”

用短句讲清活动价值：

- 不是比谁堆的功能多；
- 不是比谁调用的模型新；
- 核心是发现真实问题、证明 Agent 必要性、完成可靠实现、拿出证据并讲清楚价值。

视觉上使用一块连续叙事区域，不要做成四张等宽营销卡片。

#### D. “你会经历什么”

展示五段实践路径：

1. 发现真实问题；
2. 定义用户与价值；
3. 判断为什么需要 Agent；
4. 去外部工具构建并带回证据；
5. 用证据完成展示与评审。

桌面端可使用横向轨迹；移动端为单焦点逐段展示。滚动时只点亮当前阶段，不做传统粗重时间轴。

#### E. AI Coach 互动预览

这是主页最重要的交互模块之一。

初始只显示：

- Coach 光核；
- 一个问题；
- 一个简洁回答器。

确定性演示三幕：

1. `你最想改变的具体工作瞬间是什么？`
2. 用户回答后：`这个问题影响的是谁？损失具体体现在哪里？`
3. 用户回答后：`为什么普通大模型聊天不足以解决它？`

每一幕遵循：

```text
当前判断
最大风险
一个关键问题
一个回答器
```

但视觉上不要显示为四张卡或检查报告。通过字号、留白、Coach 状态和转场表达。

三幕完成后只展示一个“问题种子”预览和 CTA：`进入完整实践流程`。当前阶段该 CTA 可进入一个明确标注的前端预览页，不要伪装成已接入真实 AI。

#### F. 三类角色入口

三类角色应当在同一个统一产品故事中，而不是三个独立后台入口。

- 参赛者：`找到值得做的问题，并把它变成有证据的作品`
- 评委：`先独立理解项目与证据，再做人的判断`
- 组织者：`看见共性阻塞与资源需求，而不是窥探私人探索`

参赛者为主视觉；评委和组织者为次要入口。点击后进入轻量说明页，讲清“你会看到什么、你需要做什么、系统不会替你做什么”。

#### G. 平台做什么 / 不做什么

用左右对照或连续排版说明：

平台负责：

- 逐步澄清问题；
- 沉淀关键结论；
- 生成外出构建任务包；
- 接回证据并暴露缺口；
- 组织最终叙事。

平台不负责：

- 替用户决定什么值得做；
- 在网页内 Coding；
- 替代专业验证与大规模测试；
- 替评委打分；
- 替组织者执行未经确认的管理动作。

#### H. 最终 CTA

标题：`从一个具体问题开始，而不是从技术名词开始`

按钮：

- `开始一次问题探索`
- `查看活动指南`

#### I. FAQ 与 Footer

FAQ 先放 5 个问题：

1. 不会编程也可以参加吗？
2. 已经有一个想法，可以直接开始吗？
3. 平台会替我完成 Coding 吗？
4. 作品必须与工作相关吗？
5. AI Coach 会直接告诉我标准答案吗？

回答保持克制，每条 2–4 句，不写成长说明书。

## 6. 视觉系统

视觉母题：

> **安静的认知画布 Quiet Cognitive Canvas**

页面应像一张随着思考逐渐生长的白色画布，而不是企业系统首页。

### 色彩

使用 CSS 变量，组件不得直接散落硬编码颜色：

```css
--surface-canvas: #f5f7fa;
--surface-primary: #ffffff;
--surface-focus: #f8fbff;
--surface-muted: #eef2f7;

--text-primary: #172238;
--text-secondary: #667085;
--text-tertiary: #8b95a7;

--border-subtle: #e2e8f0;
--border-strong: #cbd5e1;

--accent-coach: #3568e8;
--accent-coach-soft: rgba(53, 104, 232, 0.14);
--accent-purple: #7c62e8;
--accent-evidence: #16836f;
--accent-gap: #bd7418;
--state-danger: #b54747;
```

### 字体与层级

- 中文：`PingFang SC`, `Noto Sans CJK SC`, `Microsoft YaHei`, sans-serif；
- Hero 标题桌面端约 56–68px，移动端约 38–44px；
- 模块标题 30–40px；
- 正文 15–17px，行高约 1.65；
- 不依赖全大写英文制造科技感；
- 不把大量浅灰小字当作“高级感”。

### 形态

- 8 / 12 / 18px 三档圆角；
- 边框极细，阴影极轻；
- 减少卡片数量；
- 不使用玻璃拟态大面板；
- 不使用满屏渐变背景；
- 不使用 3D 渲染感按钮；
- 不套用通用后台模板或 shadcn 默认视觉。

### Coach 光核

优先用可维护的 SVG + CSS 实现：

- 中央柔和光核；
- 2–4 层半透明薄膜轨迹；
- 极少量方向线；
- 支持 `idle`、`listening`、`challenging`、`condensing`、`confirmed` 五种状态；
- 不持续闪烁、旋转或漂浮；
- 每次状态变化都必须对应真实交互变化。

不要把整张 UI 参考图裁剪成网页背景，也不要用位图冒充可交互界面。

## 7. 动效语言

统一使用以下空间动词：

- 端上来；
- 收拢；
- 吸附；
- 长出来；
- 取到眼前；
- 退到背景；
- 凝结。

建议时长：

```text
微交互：160–200ms
内容端上：260–340ms
场景切换：480–620ms
Hero 首次编排：总时长不超过 1.2s
```

默认 easing 接近：

```css
cubic-bezier(0.22, 1, 0.36, 1)
```

禁止：

- 每句话打字机动画；
- 无意义循环呼吸；
- 粒子雨和霓虹网格；
- 同时让多个模块抢焦点；
- 动画期间锁死操作；
- 依赖动画才能理解信息。

必须支持 `prefers-reduced-motion`，缩短或取消位移与缩放，但保持信息顺序。

## 8. 默认技术方案

先尊重现有仓库。若为空仓库，使用：

- Next.js App Router；
- React + TypeScript，严格模式；
- Tailwind CSS 作为 Token 与布局工具，但不采用默认模板视觉；
- CSS Variables 管语义 Token；
- Framer Motion 管有意义的场景动效；
- Radix Primitives 管 Dialog、Popover、Tooltip 等可访问性基础；
- Lucide 或仓库已有线性图标集，统一线宽；
- Vitest + Testing Library；
- Playwright 做关键流程与视口截图。

当前阶段不需要全局状态库。轻量状态优先使用局部 reducer；只有当跨路由状态确实出现时才引入 Zustand。不要为了未来可能性过度设计。

建立清晰配置层：

```text
config/site.ts             品牌、导航、CTA、FAQ
config/activity.ts         实践路径、角色与边界文案
fixtures/coach-demo.ts     确定性三幕 Coach 演示
styles/tokens.css          语义 Design Token
```

所有活动日期、报名链接、规则文本均通过配置读取；若真实信息未提供，使用明确的 `待活动配置确认` 占位，不编造日期和数字。

## 10. 响应式

主要验收视口：

- 1440×900；
- 1024×768；
- 390×844。

规则：

- 桌面端 Hero 可左右编排，但主标题与 Coach 必须共同形成一个中心；
- 低于 768px 改为单焦点纵向场景；
- 移动端导航使用可访问抽屉；
- 角色、路径、FAQ 不能简单压成无尽卡片列表；
- Coach 回答器始终在拇指可达区域附近；
- 不出现水平溢出、被遮挡 CTA、过小点击区域或文本截断。

## 11. 无障碍与质量

- 所有按钮、链接和输入可键盘操作；
- 焦点样式清晰但克制；
- 图标按钮必须有可访问名称；
- 颜色不是唯一状态编码；
- 文本对比度满足 WCAG AA；
- Dialog 正确锁焦并返回焦点；
- Coach 场景变化用适当的 `aria-live`，避免重复朗读；
- 表单错误显示在相关输入附近，不能只用 Toast；
- 图片有正确 alt；装饰性图形使用空 alt 或 `aria-hidden`；
- 页面在无 JavaScript 失败时至少保留核心活动说明。

## 15. 非回归红线

最终必须逐条确认：

- 首屏不是项目列表或管理后台；

- 没有无限聊天流；
