## 一、欢迎你

这项活动的一句话：**由 AI Coach 陪你，把一个真实问题变成可验证的 AI Agent 作品。**

不需要你是程序员。活动的前半程，是把问题想清楚：它发生在谁身上、代价是什么、为什么需要一个 Agent 而不是一次普通的 AI 聊天。后半程，你在外部工具里把作品做出来，带回证据，完成展示与评审。

全程按五段方法推进：

1. 发现真实问题
2. 定义用户与价值
3. 判断为什么需要 Agent
4. 去外部工具构建，并带回证据
5. 用证据完成展示与评审

我们不用完成度百分比衡量你的进展，只看三样东西：**主张、证据、缺口**。

## 四、N1 详细操作指南（第 1 周）

### 4.1 入口与流程

打开活动网站，从首页（`/`）或 `/start` 进入问题探索。AI Coach 一次只问一个问题，全程 6 问，约 10–15 分钟。答完最后一问，你会得到一张可以带走的「问题定义卡」。

你可以带着一个真实问题来，也可以带着一个想法来——入口不同，Coach 的问法会略有差异，但都会先回到真实问题本身。

### 4.2 六问怎么答

前三幕，把问题立住：

| 轮次 | 主题 | Coach 在追问什么 | 怎么答 |
| --- | --- | --- | --- |
| 第 1 问 | 问题 | 你最想改变的具体工作瞬间是什么 | 写一个真实发生的瞬间：谁、在做什么、卡在哪里。粗糙没关系，具体就好 |
| 第 2 问 | 影响 | 这个问题对谁造成了什么具体损失 | 点出具体的人和代价：时间、返工、等待都算 |
| 第 3 问 | Agent 必要性 | 为什么普通大模型聊天不足以解决它 | 想想记忆、工具、固定流程、留痕——它真正需要哪一样 |

后三轮，把问题深化：

| 轮次 | 主题 | 怎么答 |
| --- | --- | --- |
| 第 4 问 | 影响量化 | 给一个粗估：大约多少人、多久发生一次、每次代价多少 |
| 第 5 问 | 可观察改善 | 写一个能看出来的信号：少了哪步、快了多久、少了什么错 |
| 第 6 问 | Agent 必要一环 | 点名流程里非 Agent 不可的一环：记忆、工具、流程或反馈，说清为什么非它不可 |

答问提示：

- Coach 是一位懂 Agent 落地的业务专家。它会优先追问业务：具体的人、具体的损失；也会自然地问出「直接用 ChatGPT 不行吗」这类问题。它严苛，但不羞辱人，也不会奉承你——被追问是流程的一部分，不是否定。
- 不需要任何技术词汇，说业务、说人、说代价。
- 一次只回答当前这一个问题。

### 4.3 隐私提醒（作答前请读）

**回答不会保存为项目，但可能发送至 AI 服务；请勿输入保密、个人或未公开信息。**

### 4.4 问题定义卡长什么样

六问答完，页面会凝结出一张「问题定义」卡。它由你的回答摘录确定性合成——平台不替你做分析，只做整理。结构如下（示意，非真实提交）：

```text
问题定义
三幕种子经三轮追问深化而成——缺口仍在，但每一条都有了可继续验证的方向。

生成时间:2026-08-20 09:05(本地时钟)
卡号:QD-XXXXX(本会话生成,未落库)
格式版本:v1
问答映射:主张←第1·3幕;影响←第2幕;深化←第4–6轮

【主张】
想改变的瞬间:<你第 1 问的回答摘录>
为什么需要 Agent:<你第 3 问的回答摘录>

【证据】
影响与损失:<你第 2 问的回答摘录>

【深化记录】
·影响量化
  问:受影响的人大约有多少、多长时间发生一次?
  答:<你第 4 问的回答摘录>
·可观察改善
  问:改善之后,你能观察到什么具体变化来说明它成立了?
  答:<你第 5 问的回答摘录>
·Agent 必要一环
  问:整个流程里,哪一步是普通大模型聊天做不到、必须靠 Agent 的?
  答:<你第 6 问的回答摘录>
深化记录来自本次会话回答的摘录,不构成已验证的证据。

【缺口】仍待深挖(诚实标注)
◇ 影响面尚未量化——受影响的人数、频次、代价还缺数字
◇ 证据尚未接回——改善主张还没有可核对的运行结果
◇ Agent 必要性尚未对照验证——还没有与普通大模型方案的实测对比
```

注意「缺口」部分：三条缺口是诚实保留的待办，不是扣分项。深化不等于解决——后续节点，就是沿着这些缺口继续验证。

### 4.5 导出字段说明

复制后，卡片以纯文本进入你的剪贴板。文本头部有四行追述信息：

| 字段 | 含义 |
| --- | --- |
| 生成时间 | 卡片凝结时刻的本地时钟读数（你电脑上的时间），不是你点击复制的时刻 |
| 卡号 | QD-XXXXX 格式，本次会话随机生成、未落库——平台还没有保存它，换新会话会变 |
| 格式版本 | v1，导出文本的格式版本 |
| 问答映射 | 卡片各部分来自哪一问：主张←第1·3幕；影响←第2幕；深化←第4–6轮 |

### 4.6 复制带走与交棒

这张卡只存在于当前页面会话中：平台不会替你保存，它也不代表项目已创建或提交。请务必当场完成三步：

1. 点击复制，把卡片纯文本带走；
2. 粘贴到 WorkBuddy 项目群（或按群内指引放入共享文件夹）；
3. 妥善保留——N2 开放后，凭这张卡继续。

## 六、平台边界

这个平台做什么：

- **澄清问题**：把模糊的想法，拷问成具体的问题定义；
- **沉淀结论**：把你的回答，凝结成可带走的卡片；
- **组织任务包**：把要做的事情整理清楚；
- **接回证据、暴露缺口**：你带回什么，就照实呈现什么；
- **组织最终叙事**：帮你把过程与证据，讲成完整的展示。

这个平台不做什么：

- 不替你决定方向——评价和取舍始终在你手里；
- 不在网页内 Coding——构建在外部工具中完成；
- 不替代专业验证与大规模测试；
- 不替评委打分——AI 有过程能力，没有人类决策权。

## 七、常见问题（FAQ）

**不会编程能参加吗？**
可以。实践路径的前半程是澄清问题、定义价值和判断 Agent 必要性，不要求写代码。实际构建在外部工具中完成，平台负责把任务包准备清楚，并帮你接回证据。

**我的回答会被谁看到？**
回答不会保存为项目，但可能发送至 AI 服务；请勿输入保密、个人或未公开信息。卡片只在你当前的浏览器会话中凝结，复制带走后由你支配。

**卡号 QD-XXXXX 是什么？**
它是本次会话随机生成的卡片标识，未落库，仅用于导出文本内的追述对照。它不是报名号，也不关联任何成绩或排名；新会话会生成新卡号。

**没有 WorkBuddy 怎么办？**
WorkBuddy 是活动协作的入口：项目群、共享文件夹都在上面。下载方式与群二维码待活动配置确认，确认后会在活动指南页（`/guide`）更新，请以活动正式通知为准。

**已经有一个想法，可以直接开始吗？**
可以。但从想法入口进入，Coach 的第一问仍会回到真实问题本身：先不描述功能，先讲你观察到的现象。方案先行是最常见的风险，值得先被检验一次。

**平台会替我完成开发和测试吗？**
不会。平台不承担 Coding、在线调试和大规模测试；验证证据由你在外部工具中产生并带回，智能体负责组织与审阅。这是刻意的边界，不是能力缺口。

**活动的时间安排是什么？**
四个节点分别在第 1–4 周，具体日期均待活动配置确认。当前只有 N1（问答初筛）开放，其余节点的开放时间以活动正式通知为准。

本手册未覆盖的问题，请在 WorkBuddy 项目群中提出，或等待活动正式通知。
