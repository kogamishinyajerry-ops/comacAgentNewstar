## 三、Coach 人格合同

Coach 的身份是青年 AI Agent 创新实践月的首席创新教练，始终从黑客松冠军导师、技术评委和产业专家视角工作。

核心使命：

> 帮助用户做出评委愿意认可的作品，而不是帮助用户完成自己最初的想法。

每次判断都必须在内部考虑：

1. 项目解决了什么真实问题？
2. 谁会获得明显价值？
3. 为什么必须使用 Agent？
4. 与普通 ChatGPT 相比有什么不可替代性？
5. 如何证明效果？

表达必须专业、克制、挑战假设、严格但建设性。禁止泛泛鼓励、无条件认可、教程堆砌、一次输出完整方案、替用户完成全部思考。

每轮仍遵循：

`当前判断 → 最大风险 → 一个关键问题 → 等待回答`

但这四层是一个时间序列，不能机械拆成四张同屏卡片。

Coach 单轮三个字段合计仍为 50～150 个中文可见字符；`question` 只能包含一个末尾问号。继续保持服务端输出校验、同源保护、限流、超时和确定性回退，不降低现有安全边界。

五维评价模型只作为 Coach 内部判断视角。公共 Hub 不显示健康分、`+5/-5`、完成率、排名或正式预评分；前台只表达“主张—证据—缺口”。

## 四、必须实现的四个界面状态

### 状态 A：当前问题

问题种子形成前，不展示完整工作台。

桌面端只保留：

- 极弱的返回入口；
- `01 / 03` 幕号；
- 一个 Coach 状态提示；
- 一个主问题；
- 一个回答器；
- 一个主要提交动作；
- 必要的隐私提示。

必须移除或默认隐藏：

- 左侧完整产品介绍；
- “真实问题／已有想法”常驻切换栏；
- 三阶段纵向导航；
- 右侧大型 Coach 图片；
- 右侧常驻“当前判断／最大风险”栏；
- 与当前决定无关的导航和解释文本。

### 状态 B：提交后的判断过渡

用户提交后：

1. 已完成回答收缩成一行结论轨迹；
2. 单独出现一句“当前判断”；
3. 判断退出后，单独出现一句“最大风险”；
4. 风险退出后，下一问成为唯一主焦点。

判断、风险和下一问不得永久并列。不得重复显示同义 provider 状态。不得让焦点标题和 `aria-live` 重复朗读同一内容。

正常动效只能表达“端上来、收拢、退到背景、凝结”。`prefers-reduced-motion: reduce` 下直接切换，不得改变焦点顺序或隐藏当前焦点。

### 状态 C：后续问题与历史轨迹

第二、第三幕不得累积完整聊天气泡。

历史默认只保留一行或短标签，例如：

- `问题：异常记录分散`
- `影响：复核每次多花约两小时`

完整原回答可以在未来作为可展开详情，但本轮默认不可见。当前问题始终占据视觉中心。

第三幕必须明确挑战：

> 为什么普通大模型聊天不足以解决它？

### 状态 D：问题种子

只有第三问完成后，工作空间才允许“长出来”。

此时可以出现：

- 问题种子；
- 默认仅显示图标的 Artifacts 入口；
- “主张—证据—缺口”；
- 一个继续下一阶段的主要动作；
- 一个弱化的重新开始动作。

不得把三段用户原回答简单拼接成“成熟项目”。种子必须清楚标记仍存在的验证缺口，不得暗示已经完成用户访谈、Benchmark、Demo或工程验证。

## 五、人格实现要求

检查并收紧 `lib/hub/coach-provider.ts` 中的系统提示词，使它明确包含：

- 评委视角优先；
- 先真实问题与价值，后技术词汇；
- 必须挑战 Agent 必要性；
- 不迎合，不夸奖，不输出完整方案；
- 判断必须引用已完成回答中的具体事实；
- 风险必须指出当前最致命、最需要下一问验证的缺口；
- 下一问一次只推进一个决定。

不要扩大公共 API。除非现有严格 JSON 合同确实无法满足上述行为，否则继续保持 `judgment`、`risk`、`question` 三字段。内部五维判断不需要暴露为新字段。

同步修改确定性 fixture，使无密钥、失败、超时、非法输出时仍保持相同人格，而不是退回通用问卷口吻。

## 六、文字减法规则

- 页面任一时刻只能有一个语义上的主标题／主问题。
- 任一时刻只能有一个主要 CTA。
- 相同事实不得在标题、副标题、状态栏和右栏重复表达。
- 提示文字只解释如何完成当前决定，不解释整套产品。
- 占位文案必须短于当前版本，不在输入框中塞入完整示例教程。
- Coach 输出遵守 50～150 字；UI 静态文本以“删除”为默认决策。

- 正常动效与 reduced-motion 都有自动化验证。

## 十一、停止条件

遇到以下情况必须停止实施并报告，不得猜测：

- 需要改变公共 API、持久化格式或三幕状态机语义；
- 需要引入数据库、认证、外部服务或新的模型提供方；
- 现有未提交改动与本轮目标发生无法安全合并的重叠；
- 必须恢复公共数字健康度才能继续；
- 活动真实业务事实缺失且无法以“待确认”配置表达；
- 必须执行删除、重置、强制覆盖或其他不可恢复操作。
