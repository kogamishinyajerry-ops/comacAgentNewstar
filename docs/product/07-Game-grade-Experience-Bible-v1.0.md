## 0. 一句话定义

这不是“把活动网站做成游戏”。

这是把成熟游戏制作中最有价值的能力——**场景编排、行动后果、世界状态、角色反馈、节奏、音画与质量门槛**——用于一个严肃的 AI Coach 认知体验：

> 用户每交出一个判断，问题世界就多长出一层结构；  
> 用户每带回一份证据，项目世界就多获得一处支撑。

体验最终要让用户感到：

> 我刚才完成了一次真实判断，空间因此发生了变化。

而不是：

> 我点击了一个按钮，系统奖励了我积分。

## 1. 继承关系：哪些原则绝不重开

本 Bible 继承并强化以下既有非协商项：

1. **强编排，弱干预。** 系统控制认知负担和信息出现顺序，不替人作出结论。
2. **一问一幕，一幕一决策。** 同一时刻只有一个主要问题、一个主要回答器和一个清晰下一步。
3. **当前场景拥有视觉焦点。** 历史、轨迹、Artifacts 和解释层都必须退后。
4. **业务故事优先。** 先明确真实问题、影响和证据，再讨论 Agent、Workflow、RAG、MCP 或 Benchmark。
5. **Coach 严格但建设性。** 它挑战假设，不迎合，也不代替用户完成全部思考。
6. **平台不承担 Coding 与大规模测试。** 实际构建在外部工具中完成，平台负责任务交接与证据回流。
7. **证据优先于完成率。** 核心模型仍是“主张—证据—缺口”，不是伪精确健康分。
8. **AI 没有人的裁决权。** 参赛者、评委和组织者保留正式判断与责任。
9. **安静的认知画布。** 不退化为驾驶舱、监控大屏、赛博朋克控制台或通用 SaaS 模板。
10. **动效必须解释状态变化。** 只使用“端上来、收拢、吸附、长出来、取到眼前、退到背景、凝结”等空间动词。
11. **真实 DOM 与可访问性优先。** 视觉层不得吞掉文本、键盘、焦点、语义和降级路径。
12. **产品事实保持诚实。** 未配置日期、报名、规则、品牌资产或完整后端能力不得被体验包装掩盖。

Game-grade 不是第十三条装饰风格，而是让上述十二条被用户**直接感受到**。

## 2. 体验立场：顶级感从哪里来

### 2.1 顶级感不来自素材数量

不以以下指标衡量“游戏级”：

- 页面里有多少粒子；
- 是否有 3D；
- 是否有开场视频；
- 是否有背景音乐；
- 是否有积分、等级、徽章；
- 是否堆满卡片和动态图表；
- 是否像某一款知名游戏。

顶级感来自六个一致性：

| 维度 | 体验要求 |
| --- | --- |
| 美术指导 | 所有表面属于同一个世界，形状、材质、颜色、留白与光线有共同语法 |
| 场景设计 | 每一幕只处理一个认知任务，用户始终知道自己在看什么 |
| 行动后果 | 每次输入、确认、带回证据都会改变可见世界状态 |
| 角色反馈 | Coach 的状态与语言来自真实流程状态，不循环表演 |
| 节奏控制 | 信息不是同时堆出来，而是按理解顺序被端上、收拢、凝结 |
| 质量门槛 | 响应式、键盘、Reduced Motion、性能和回归测试与视觉同等重要 |

### 2.2 游戏设计服务于判断力

本产品的“玩家能力”不是反应速度、操作熟练度或刷取时长，而是：

- 能否发现真实问题；
- 能否缩小模糊范围；
- 能否区分主张与证据；
- 能否说明为什么需要 Agent；
- 能否承认失败和缺口；
- 能否在证据不足时保留不确定性；
- 能否承担最终判断。

因此，体验奖励不是“更多分数”，而是：

> 模糊世界逐渐变得可描述、可验证、可承担责任。

## 3. 核心世界模型

全产品统一采用一个可持续扩展的世界隐喻：

# 问题种子 → 决策生长 → 证据凝结

### 3.1 问题种子

问题种子不是装饰图标，也不是项目完成证明。

它是三类最小判断的临时凝结：

1. **真实瞬间**：具体在什么时候、什么场景发生；
2. **具体影响**：谁受到什么可观察损失；
3. **Agent 必要性**：为什么普通聊天或更简单方式不足。

未经验证的内容保持轻、开放、允许被推翻。

### 3.2 决策生长

用户提交回答后，空间只长出与该回答直接相关的一层：

- 第一问后，真实瞬间获得边界；
- 第二问后，影响关系开始连接；
- 第三问后，Agent 必要性成为可检查主张；
- 形成问题种子后，Artifacts 工作空间才允许出现。

不提前展示完整工作台，不用阶段导航暗示用户已经拥有尚未形成的成果。

### 3.3 证据凝结

后续完整产品中：

- 主张没有证据时，结构可以存在，但保持悬空；
- 证据被带回时，主张与证据形成可见连接；
- 失败案例不是扣分，而是使边界更可信；
- 被推翻的主张进入轨迹，不被悄悄删除；
- 缺口保持可见，直到用户作出下一轮判断。

世界状态由“稳定/漂移、连接/悬空、清晰/模糊、实线/虚线”表达，不依赖红黄绿交通灯和完成百分比。

## 4. 核心体验循环

完整产品的主循环定义为：

```text
观察一个真实瞬间
→ 作出一个可承担的判断
→ 凝结为主张或任务
→ 去外部工具构建/验证
→ 带回证据、失败与人工修改
→ 解释证据支持了什么
→ 暴露新的缺口
→ 决定下一轮
```

这个循环的游戏设计对应关系：

| 产品动作 | 游戏制作能力 | 禁止误读 |
| --- | --- | --- |
| Coach 提出一个问题 | 场景目标 | 不是任务清单 |
| 用户提交判断 | 玩家行动 | 不是答题得分 |
| 内容收拢为节点 | 行动后果 | 不是成功 Toast |
| Artifact 点亮 | 世界状态解锁 | 不是掉落奖励 |
| 外出构建任务包 | 出发准备 | 不是平台内运行假进度 |
| 证据回流 | 任务结算 | 不是“完成率 +10%” |
| 快照提交 | 保存点/阶段结局 | 不是冻结全部私人探索 |

## 5. 场景语法

### 5.1 每一幕的最小结构

逻辑上，每幕仍然包含：

```text
当前判断
↓
最大风险
↓
一个关键问题
↓
等待用户回答
```

视觉上不得拆成四张并列审计卡。

当前问题必须拥有：

- 最大字号或最高对比；
- 最清晰的空间位置；
- 唯一主要回答器；
- 唯一主要提交动作；
- 可见但不抢焦点的 Coach 状态；
- 少量与本幕相关的上下文。

### 5.2 场景进入

进入一幕时，顺序是：

1. 上一幕结果完成收拢；
2. Coach 显示当前判断；
3. 最大风险短暂停留；
4. 新问题被端到前景；
5. 回答器获得明确焦点。

不得让新问题、旧问题、风险、解释和下一阶段同时出现。

### 5.3 场景退出

用户提交后：

1. 回答器失去主导权；
2. 当前内容向种子轨或问题卡吸附；
3. 可见世界状态发生一次明确变化；
4. 才进入下一幕。

不得只通过按钮禁用、加载转圈或成功提示表达推进。

### 5.4 历史

历史默认压缩为：

- 三个短槽位；
- 一条决策轨迹；
- 或一个可打开的回看抽屉。

禁止退化为无限聊天记录。完整回看属于“取到眼前”的次级动作，关闭后应回到原场景并恢复焦点。

## 6. Coach：角色、表演与状态

### 6.1 角色定位

Coach 是：

- 首席创新教练；
- 评委视角的挑战者；
- 严格但建设性的伙伴；
- 帮用户看见风险的人；
- 保留人类裁决权的流程角色。

Coach 不是：

- 吉祥物；
- 拟人机器人；
- 夸奖型聊天助手；
- 自动方案生成器；
- 评分裁判；
- 持续吸引注意力的动态 Logo。

### 6.2 五种正式视觉状态

| 状态 | 认知含义 | 视觉行为 |
| --- | --- | --- |
| `idle` | 等待用户判断 | 稳定、收束、几乎静止 |
| `listening` | 用户正在输入 | 向回答器轻微展开 |
| `challenging` | 发现矛盾或风险 | 轮廓集中，方向性增强 |
| `condensing` | 内容正在收拢 | 膜层与线索向核心聚合 |
| `confirmed` | 阶段成果形成 | 短暂稳定后安静停留 |

任何视觉变化必须由真实状态触发。不得使用永久旋转、呼吸发光、随机粒子或与状态无关的循环动画制造“AI 感”。

### 6.3 台词节奏

默认输出仍为 50～150 字，少说、多问。

高质量台词应让用户明确：

- 当前已有哪一条判断；
- 最大的不确定性是什么；
- 现在只需要回答哪一个问题。

不得用长教程代替场景，也不得用泛泛鼓励稀释风险。

---

## 7. 行动后果系统

每个主要动作必须至少产生一种可解释后果：

| 用户动作 | 必须出现的后果 |
| --- | --- |
| 输入并提交第一问 | “真实瞬间”槽位从幽灵态变为已沉淀 |
| 提交第二问 | 影响关系获得可见连接 |
| 提交第三问 | 三个槽位收拢为问题种子 |
| 打开 Artifact | 当前场景退到背景，成果被取到眼前 |
| 导出任务包 | 形成明确的外出构建边界和证据要求 |
| 上传证据 | 证据与对应主张建立连接 |
| 承认失败 | 世界边界变得更可信，不以扣分羞辱用户 |
| 形成评审快照 | 只收拢用户确认交出的判断与证据 |

禁止用以下反馈替代后果：

- `+10 XP`；
- “恭喜完成”；
- 随机烟花；
- 徽章弹窗；
- 排名变化；
- 假完成百分比；
- “击败 X% 参赛者”。

---

## 8. Artifacts：安静的成果系统

Artifacts 是思考和证据沉淀后的对象，不是预置文件柜。

### 8.1 默认状态

- 默认只显示图标或极短名称；
- 未形成的 Artifact 不以空卡片占位；
- 当前不需要的内容退到背景；
- 点击后才进入聚焦层；
- 关闭后恢复原来的场景位置和键盘焦点。

### 8.2 建议顺序

后续完整链条可沿既有人格规范逐份点亮：

1. 问题定义；
2. 用户与场景；
3. Agent 方案；
4. Workflow；
5. 验证计划与 Benchmark；
6. 证据集；
7. Demo 叙事；
8. 答辩材料。

本版工程授权只保留已有“问题定义 Artifact”，不新增第二份 Artifact。

## 9. 两个世界的强度控制

### 世界 A：公共官网与体验序章

目标：让人愿意进入。

允许：

- 更完整的构图；
- 一次性的电影式场景进入；
- 更明显的世界隐喻；
- 低频环境深度；
- 一个可跳过的短序章；
- 30～60 秒的可玩认知演示。

仍然禁止：

- 强制观看；
- 自动播放声音；
- 持续粒子；
- 赛博朋克大屏；
- 大量营销卡片；
- 虚构活动事实。

### 世界 B：Coach 工作空间

目标：让人愿意思考且不疲劳。

采用：

- 单焦点；
- 克制动态；
- 清楚状态后果；
- 小范围空间变化；
- 真实输入与可访问表单；
- 安静持久的决策轨迹。

序章结束后，体验强度必须主动下降，把注意力交还给问题本身。

## 10. 美术语言

### 10.1 视觉母题

继续使用：

> 安静的认知画布（Quiet Cognitive Canvas）

新增的 game-grade 层只引入“世界状态”，不引入新的品牌皮肤。

### 10.2 颜色职责

- 深海军蓝：主要文字与结构；
- 钴蓝：Coach、当前焦点和已建立连接；
- 极少淡紫：质询、矛盾或认知转折；
- 青绿：证据获得支撑；
- 琥珀：缺口和待验证；
- 浅色纸面：长期工作背景。

颜色不单独承担语义，必须与文字、形态或线型共同表达。

### 10.3 形状职责

- 圆与柔和膜层：Coach、开放探索；
- 细线与节点：决策轨迹、关系；
- 稳定矩形面：已形成的 Artifact；
- 虚线或未闭合轮廓：缺口、待验证；
- 不对称但平衡的构图：避免 SaaS 卡片阵列。

### 10.4 材质

- 轻纸面、半透明膜层、低反差玻璃感；
- 不使用厚重金属、镭射霓虹、塑料玩具质感；
- 阴影表达层级，不表达炫技；
- 背景纹理不得影响文字对比与阅读。

## 11. 动效圣经

### 11.1 正式动词

| 动词 | 用途 |
| --- | --- |
| 端上来 | 新问题、新选择进入当前焦点 |
| 收拢 | 一幕完成，内容退出主舞台 |
| 吸附 | 回答沉淀到问题槽位或轨迹 |
| 长出来 | 工作空间或 Artifact 因真实状态形成 |
| 取到眼前 | 用户主动查看成果或证据 |
| 退到背景 | 历史或非当前对象让出焦点 |
| 凝结 | 多条判断形成问题种子或快照 |

### 11.2 时间基线

```text
微交互：160–200ms
内容端上：260–340ms
场景转换：480–620ms
一次性体验序章退出：不超过 700ms
首屏整体编排：不超过 1.2s
```

推荐 easing：

```css
cubic-bezier(0.22, 1, 0.36, 1)
```

### 11.3 禁止动态

- 永久旋转；
- 永久呼吸光；
- 粒子雨；
- 循环闪烁；
- 每次点击都弹跳；
- 因装饰而移动的背景；
- 必须等待结束才能操作的长动画；
- Reduced Motion 下丢失信息。

### 11.4 Reduced Motion

`prefers-reduced-motion: reduce` 下：

- 跳过序章退出时长；
- 取消位移、缩放和模糊转场；
- 保留状态文字与静态层级变化；
- 焦点顺序与正常模式一致；
- 不隐藏任何内容。

## 12. 声音原则

声音属于后续可选增强，不进入本次 Vertical Slice。

未来接入时必须满足：

- 默认静音；
- 第一次播放前取得明确许可；
- 不使用持续背景音乐；
- 只为 Coach 唤醒、凝结、证据连接、快照形成等关键状态提供极短反馈；
- 声音不能承担唯一语义；
- 办公环境下可完全关闭且不损失体验。

---

## 13. 性能、可访问性与降级

Game-grade 不允许以牺牲工程质量为代价。

### 13.1 DOM 与输入

- 正文、问题、回答器、按钮和链接使用真实 DOM；
- 核心交互不放入 Canvas；
- 键盘可以完成完整切片；
- 焦点进入、退出和返回均可预测；
- 输入内容不因视觉转场丢失；
- 辅助技术能获得当前问题、状态和错误。

### 13.2 视口

正式验收：

- 1440×900；
- 1024×768；
- 390×844。

要求：

- 无水平溢出；
- 固定视口工作台不产生页面级纵向滚动；
- 移动端不机械堆叠桌面多栏；
- 回答器位于可触达区域；
- 主要问题与 CTA 不被 HUD 或系统 UI 遮挡。

### 13.3 资源与渲染

- 不新增运行时 3D 引擎；
- 不新增重型动效依赖；
- 优先复用现有生产级 WebP 与 CSS/SVG；
- 装饰资源不得承载业务事实；
- 动画只改变 `transform`、`opacity` 等低成本属性；
- JS 失效时，核心 Coach 内容仍有可理解的静态页面。

## 14. QA 与非回归

每一条 game-grade 切片必须同时通过四类验收：

### 14.1 产品验收

- 是否仍然一问一幕；
- 是否没有隐藏分数；
- 是否没有替用户形成结论；
- 是否没有扩大为 Coding、Benchmark 或完整 Artifact 平台；
- 是否诚实标注当前能力边界。

### 14.2 体验验收

- 用户是否在 10 秒内知道当前唯一动作；
- 提交回答后是否看见可解释后果；
- 序章结束后视觉焦点是否回到问题；
- 世界状态是否与真实流程状态一致；
- 是否没有无意义持续动画。

### 14.3 无障碍验收

- 序章可以键盘启动或跳过；
- 序章存在时底层工作台不可误操作；
- 序章结束后焦点进入回答器；
- Reduced Motion 完整可用；
- 语义状态有文本替代；
- 三视口无溢出。

### 14.4 工程验收

- lint；
- typecheck；
- unit tests；
- production build；
- 既有 e2e；
- 本切片新增 Playwright 流程。

未实际运行的检查不得声称通过。

## 15. 本版唯一 Vertical Slice 合同

### 15.1 路由

```text
/experience
/experience?entry=idea
```

它是一个**可选的沉浸式入口**，不替换 `/` 与 `/start` 的简洁模式。

### 15.2 切片边界

只实现以下完整体验：

```text
一次性体验序章
→ 用户主动“唤醒问题”
→ 三幕 Coach 问题探索
→ 每次回答改变种子形成轨迹
→ 三个判断收拢为问题种子
```

复用既有 Coach 状态机、Provider 回退、附件、回看、种子与问题定义 Artifact；不重写业务逻辑。

### 15.3 序章

序章只承担三件事：

1. 建立“问题种子”的世界隐喻；
2. 告诉用户每次判断都会改变空间；
3. 交出一个明确动作：`唤醒问题`。

同时提供低强调的 `直接进入简洁模式`。

序章：

- 不自动播放声音；
- 不强制倒计时；
- 可用 Escape 或按钮结束；
- Reduced Motion 下即时结束；
- 不出现虚构分数、角色、项目或活动事实。

### 15.4 持久世界状态

工作台上方显示一条克制的三节点轨迹：

1. 真实瞬间；
2. 具体影响；
3. Agent 必要性。

它只表达：

- 当前在哪一层；
- 哪一层已由用户回答沉淀；
- Coach 是否正在重排线索；
- 问题种子是否已经凝结。

它不是阶段导航、完成率或评分条。

### 15.5 明确非目标

本 PR 不实现：

- 新 Artifact；
- 登录与持久化；
- 外出构建任务包；
- 证据上传与评审快照；
- 声音系统；
- Rive/Three.js；
- 新后端或模型接口；
- 排行、积分、徽章、健康度；
- 整站视觉重写。

### 15.6 完成定义

Vertical Slice 只有同时满足以下条件才可合并：

- `/experience` 可真实操作；
- 序章键盘可达；
- 序章关闭后焦点进入 Coach 回答器；
- 三幕业务逻辑保持既有实现；
- 每次回答更新三节点轨迹；
- 问题种子形成时轨迹完成凝结；
- 1440×900、1024×768、390×844 无页面溢出；
- Reduced Motion 无信息损失；
- `/`、`/start` 及既有角色路由不被重写；
- 新增 Playwright 覆盖序章、行动后果、移动端与 Reduced Motion。

## 16. 版本治理

后续任何“更像游戏”的提案，必须先回答四个问题：

1. 它帮助用户理解了什么状态变化？
2. 它让哪一个判断后果更清楚？
3. 去掉后，产品是否更难理解？
4. 它是否引入新的注意力、性能、无障碍或治理成本？

若前三问没有明确答案，或第四问成本大于认知收益，该提案不进入产品。

本 Bible 的目标不是让产品显得会玩，而是让严肃思考拥有与顶级游戏相同的**节奏、反馈、世界一致性和完成度**。
