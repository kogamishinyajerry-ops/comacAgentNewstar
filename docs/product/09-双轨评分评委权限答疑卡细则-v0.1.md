## 1. ⚑D5 双轨评分细则

**形态：角色绑轨。** 技术评委只打技术轨、业务专家只打业务轨，部门联络员不打分。
复用旧侧评审分配制、回避机制与评分锁定（`app/(app)/judge/`、`lib/control/`）。

**分值结构：** 各轨 4 条指标 × 每条 25 分，三档勾选（差 5 / 中 15 / 优 25），
各轨满分 100；**总分 =（业务轨 + 技术轨）÷ 2，满分 100**。对外口径「满分 100，双轨对等」。

**业务轨条目（问题卡同构版，每条 ← 对应问题卡字段）：**

| # | 条目 | 对应 |
| --- | --- | --- |
| 业一 | 问题真实具体，有真实用户与场景 | ← 主张 |
| 业二 | 影响可量化或可举出实例 | ← 证据 |
| 业三 | 证据如实、缺口不注水 | ← 证据 + 缺口 |
| 业四 | 值得做成 Agent 而非常规问答 | ← Agent 必要性 |

**技术轨条目（会议口径「智能体实现 + 代码质量」的落地）：**

| # | 条目 |
| --- | --- |
| 技一 | Agent 必要环节真实实现（非单轮问答包装） |
| 技二 | 代码仓库可核验 |
| 技三 | 测试覆盖常规 + 失败案例 |
| 技四 | 四周迭代痕迹真实 |

**配套约定：**

- 定性两条（最有价值点 / 最需改进）沿用旧侧机制，双轨通用；
- AI 第二意见**不进分数**，评委端展示并标注「仅供参考」；
- 预赛/决赛轮次是否同表（预赛可否只评业务轨）**待活动配置确认**，不阻塞本细则。

## 2. ⚑D6 评委权限矩阵

| 角色 | 项目范围 | 数据范围 | 评分权 |
| --- | --- | --- | --- |
| 技术评委 | 分配给本人的项目 | 所分配项目**全部交付包材料**（问题卡/测试资产/代码仓库引用/Demo/过程证据） | 只填技术轨 |
| 业务专家 | 分配给本人的项目 | 同上（全部交付包材料） | 只填业务轨 |
| 部门联络员（新角色 LIAISON） | 本部门全部队伍 | **只读概览**：进度、参与情况；不见评分、不见其他部门 | 无 |

- **部门归属数据**：参赛者注册/组队时**自选所属部门**（下拉），部门清单收敛在
  活动配置（`config/activity`），未配置时显示「待活动配置确认」；联络员按部门
  自动匹配本部门队伍。部门字段一次采集，概览/筛选/统计全链路复用。
- AI 第二意见：对评委可见，标注「仅供参考」。
- 复用旧侧：项目分配制（assign）、回避（recuse）、评分锁定（lock）。

## 3. ⚑D7 提问答疑卡（N2 工单落地形态）

**字段：**

| 字段 | 说明 |
| --- | --- |
| 关联问题卡号 | 自动带出（D3 过渡解已预留会话卡号；P2 落库后为全局卡号） |
| 场景卡片 | 问题卡主张摘录，自动填充、可修改 |
| 目标 | 参赛者想验证什么 |
| 技术手段 | 已尝试的手段/技术栈（辅导团队据此分派） |
| 目前困难 | 卡在哪里，为何超出智能体验证能力范围（⚑D8=A 边界） |
| 期望答复时限 | 3 日内 / 一周内 |

**流转规则：**

1. 参赛者提交 → 答疑卡进入**智能体辅导团队负责人**工作列表（总控台侧）；
2. 负责人**直接答复**（无组织者审核瓶颈）→ 参赛者收站内通知（复用旧侧 notice）；
3. 状态流转：已提交 → 已答复；
4. **超时提醒**：超过期望时限未答复的卡在总控台标黄；组织者可见整体答疑负担，
   不插手答复内容；
5. 组织侧流转进**动作注册表**（Activity Control），不做新 dashboard。
