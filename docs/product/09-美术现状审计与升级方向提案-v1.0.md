# 美术现状审计与升级方向提案 v1.0

> 范围：`/experience` 的“序章 + 问题种子凝结”两个节拍  
> 基线：PR #2 `codex/game-grade-experience-vertical-slice@16d846f`  
> 日期：2026-08-21

## 1. 现状审计

### 已成立的设计

- `/experience` 已把 Game-grade 定义为“行动后果可见”，而不是 XP、徽章、排行榜或特效堆叠。
- 序章保持单一主动作，并在退出后把焦点交给真实 Coach 输入框。
- 三节点 journey 只读现有 DOM 契约，没有建立第二套业务状态。
- 现有美术语言是暖白画布、克制钴蓝、纸张与工程线框；它与“安静认知画布”一致。
- 首屏背景复用已优化的 `hub-hero-cognitive-canvas.webp`（21,078 B），不需要新的大图。

### 美术完成度缺口

1. 序章右侧“种子坐标”已有世界观，但缺少“当前等待什么”的编辑层，画面更像一张静态概念卡。
2. 第三次判断后，Coach 内部会进入种子态，但 wrapper 的“凝结结果”在视觉上仍偏隐，行动后果没有成为一个清晰节拍。
3. Game-grade CSS 仍有 `px` 字号；Forced Colors 下 journey 的当前、完成、未来状态缺少形状区分。
4. 移动端导航抽屉与序章同时存在时，`Esc` 可被两层同时处理；序章期间 skip-link 也未指向当前唯一场景。

## 2. 升级方向：问题场 / Seed Field

本轮不增加一个“游戏界面”，而是让现有空间像一张正在记录判断的场。序章中，右侧种子台以“等待真实线索”开始；每次回答只改变已有 journey 的一层。第三层完成时，右侧结果标记从“等待判断”收束为“问题种子 / 已凝结”。

这个方向服务于 Game-grade Bible 的原因是：视觉变化只在真实状态改变时发生；它提高信息的凝结感，不制造奖励、连续刺激或伪进度。

## 3. 资产管线与性能预算

- 本切片新增美术资产：**0 B**。
- 复用已在仓库登记的 WebP 与现有 CSS 材质；不外链，不把概念参考图当产品事实。
- 新依赖：**0**；新请求：**0**；新业务状态：**0**。
- 动效只使用 `opacity` / `transform`，不引入持续循环、滤镜动画或 Canvas/WebGL；种子态只保留“种子卡落位”一个主视觉焦点。
- 路由新增压缩 CSS + JS 目标不超过 **8 KiB**；构建后记录实际差值。
- `prefers-reduced-motion: reduce` 下动效立即完成；`forced-colors` 下用系统色、实心/双线/虚线区分三种状态。

## 4. 唯一 Vertical Slice

### 包含

- 深化序章的种子台构图、编辑层和字体层级。
- 为 journey 第三栏增加基于真实 DOM 快照的“本轮产物”标记，第三问后一次性凝结。
- 只读原有 `.coach-workspace-grid`、`data-coach-progress`、`data-coach-slot-filled`、`data-artifact-lit` 契约。
- 清偿本切片直接触及的 P2：Game-grade 字号 rem 化、Forced Colors 状态区分、`Esc` 单一处理、skip-link 指向序章。

### 不包含

- 不改 Coach 状态机、Provider、附件、评审或 Artifact 语义。
- 不引入持久化游戏状态，不移植 Act5 的 `intro` phase。
- 不改 `/`、`/start` 或全站视觉。
- 不处理未触及的 npm audit、Coach 提交焦点瞬态、390px 幽灵槽裁切或 aria-label CSS 精确匹配债务。
