## 3. 场景切换语法（五拍规范）

每一拍必须回答三问：**我在哪 / 刚发生了什么 / 接下来是什么**。
一屏一焦点；动效只解释状态变化；`prefers-reduced-motion` 全降级；pending 事实诚实标注。

| 拍 | 时刻 | 回答的疑问 | 现状 |
| --- | --- | --- | --- |
| ① 建立 | 进站 → 第一问 | 我在哪、要投入什么、会得到什么 | **缺**（需新增） |
| ② 推进 | 幕/轮之间 | 流程在前进 | 已有（`motion-step-in` + 计数器） |
| ③ 凝结 | 提交回答 | 我的回答去了哪 | 已有（槽位脉冲 + sr 播报） |
| ④ 揭示 | 种子/问题定义卡 | 这张卡从哪来、可信吗 | 半有（缺溯源编排） |
| ⑤ 交棒 | 节点终章 | 接下来干什么、什么时候回来 | **缺**（需新增） |

## 4. 建立拍与交棒拍的具体形态

**建立拍**（仅第一幕尚无任何回答时呈现，同一状态机的一个前置场景，非弹窗轮播）：
三件套三步（WorkBuddy〔待确认〕→ 项目群〔待确认〕→ 现在：拷问）＋ 本页流程
（6 问、约 10–15 分钟、产出一张可带走的问题定义卡）＋ 隐私披露前置 →「开始第一问」。

**交棒拍**（每节点终章，文案按节点不同，全部可用 pending 诚实表达）：

- **N1 终章（现在即可做）**：已复制带走 → 粘贴到项目群/共享文件夹 →
  「中期答疑（第 2 周〔待确认〕）开放后，凭此卡继续」；
- N2 终章（未来）：验证反馈已记录；答疑卡已提交辅导团队负责人；N3 预告；
- N3 终章（未来）：精修完成度以主张—证据—缺口表达（不做百分比）；N4 提交窗口预告；
- N4 终章（未来）：交付包已提交；评审安排说明；活动结束致谢。

**揭示拍溯源编排**：卡揭示时六轮回答摘录依次落位到对应槽（一次编排、
reduce-motion 分支），注记沿用「来自本次会话回答的摘录，不构成已验证的证据」
——同时服务 ⚑D3 最小追溯。

## 5. 逐节点能力差距与宪法红线

**N1 问答初筛**：已交付。仅余 ⚑D1–⚑D3 拍板项与旅程叙事轮（§7）。

**N2 中期答疑**（全部新增，批次 P2/P4）：

- 测试资产接入：参赛者自带测试用例、运行证据、代码仓库引用的接收与组织；
- 智能体验证反馈链路；
- 答疑卡生成与提交（收件人：辅导团队负责人；组织侧流转进动作注册表，不做新 dashboard）。

红线 ⚑D8：宪法「平台不执行 Coding 或大规模测试」——「帮忙测试验证」的定位必须是
**组织与审阅参赛者自带的测试证据、对照其问题定义卡给反馈**。
**已拍板（2026-08-20）：选 A。** 智能体不代跑验证，N2 反馈与 N4 评委侧验收同按此定位；
宪法零修订，无需放宽。

**N3 交付冲刺**（新增，落在 Artifacts 框架内，不新增仪表盘）：

- Demo 脚本 / 答辩材料类 Artifact 的深化流（§22 方案 B 阶梯的自然延伸）；
- 精修反馈链路；旧侧「三项轻交付」生成器（`lib/deliverables.ts`：一页小实验卡、
  可见结果清单、90 秒 Demo 脚本）是现成底座。

**N4 提交评分**（新增，批次 P3/P4）：

- 交付包构成（⚑D9，**同时回填 §28 完成态开放决策**：完成态 = 完整交付包 +
  全过程证据，而非任何百分比。**构成已确认 2026-08-20**：问题定义卡 + 测试资产 +
  代码仓库引用 + Demo/答辩材料 + 过程证据；具体规格随 N4 批次设计定稿）；
- 评委侧智能体辅助验收：与 ⚑D8 同一边界问题（验收 = 核对参赛者自带证据，
  平台不代跑）；
- 过程能力计入评分：**旧侧「对话形成过程卡」（`lib/chat-insight.ts`：对话轮数、
  字段落表、口述测试、拷问答卷）正是「全过程思考/迭代能力」的现成资产**——
  N1–N3 会话证据一旦持久化（P2）即可全链路复用；
- 红线：智能体输出 = 验收清单核对与证据摘要，**评分决策权在人类评委**
  （非协商项「AI 有过程能力，无人类决策权」）。
